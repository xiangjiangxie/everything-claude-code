# 构建与修复

以最小、安全的变更增量修复构建和类型错误。

## 第 1 步：检测构建系统

识别项目的构建工具并运行构建：

| 指标 | 构建命令 |
|-----------|---------------|
| `package.json` 含 `build` 脚本 | `npm run build` 或 `pnpm build` |
| `tsconfig.json`（仅 TypeScript） | `npx tsc --noEmit` |
| `Cargo.toml` | `cargo build 2>&1` |
| `pom.xml` | `mvn compile` |
| `build.gradle` | `./gradlew compileJava` |
| `go.mod` | `go build ./...` |
| `pyproject.toml` | `python -m compileall -q .` 或 `mypy .` |

## 第 2 步：解析和分组错误

1. 运行构建命令并捕获 stderr
2. 按文件路径分组错误
3. 按依赖顺序排序（先修复导入/类型，再修复逻辑错误）
4. 统计总错误数用于进度追踪

## 第 3 步：修复循环（每次一个错误）

对每个错误：

1. **读取文件** — 使用读取工具查看错误上下文（错误行周围 10 行）
2. **诊断** — 识别根因（缺少导入、类型错误、语法错误）
3. **最小修复** — 使用编辑工具进行解决错误的最小变更
4. **重新运行构建** — 验证错误已消除且无新错误引入
5. **继续下一个** — 处理剩余错误

## 第 4 步：防护措施

在以下情况停止并询问用户：
- 修复 **引入的错误多于解决的**
- **3 次尝试后同一错误仍然存在**（可能是更深层问题）
- 修复需要 **架构层面的变更**（不仅仅是构建修复）
- 构建错误源于 **缺少依赖**（需要 `npm install`、`cargo add` 等）

## 第 5 步：总结

显示结果：
- 已修复的错误（附文件路径）
- 剩余的错误（如有）
- 引入的新错误（应为零）
- 对未解决问题的建议后续步骤

## 恢复策略

| 情况 | 操作 |
|-----------|--------|
| 缺少模块/导入 | 检查包是否已安装；建议安装命令 |
| 类型不匹配 | 读取两个类型定义；修复更窄的类型 |
| 循环依赖 | 用导入图识别循环；建议提取 |
| 版本冲突 | 检查 `package.json` / `Cargo.toml` 的版本约束 |
| 构建工具配置错误 | 读取配置文件；与可用的默认值对比 |

为安全起见，每次修复一个错误。优先选择最小差异而非重构。
