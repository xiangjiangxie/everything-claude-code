# /learn-eval - 提取、评估、然后保存

在写入任何技能文件之前，扩展 `/learn` 增加质量关卡、保存位置决策和知识放置意识。

## 提取内容

查找以下内容：

1. **错误解决模式** — 根因 + 修复 + 可复用性
2. **调试技巧** — 非显而易见的步骤、工具组合
3. **变通方案** — 库特性、API 限制、版本特定修复
4. **项目特定模式** — 约定、架构决策、集成模式

## 流程

1. 回顾会话中可提取的模式
2. 识别最有价值/最可复用的洞察

3. **确定保存位置：**
   - 自问："这个模式在其他项目中有用吗？"
   - **全局**（`~/.claude/skills/learned/`）：可跨 2+ 个项目使用的通用模式（bash 兼容性、LLM API 行为、调试技巧等）
   - **项目**（当前项目的 `.claude/skills/learned/`）：项目特定知识（特定配置文件的怪癖、项目特定的架构决策等）
   - 不确定时选择全局（全局 → 项目移动比反向更容易）

4. 使用以下格式起草技能文件：

```markdown
---
name: pattern-name
description: "不超过 130 个字符"
user-invocable: false
origin: auto-extracted
---

# [描述性模式名称]

**Extracted:** [日期]
**Context:** [适用场景简述]

## Problem
[此模式解决什么问题 - 要具体]

## Solution
[模式/技巧/变通方案 - 带代码示例]

## When to Use
[触发条件]
```

5. **质量关卡 — 检查清单 + 综合裁定**

   ### 5a. 必需的检查清单（通过实际读取文件验证）

   在评估草稿前执行以下 **全部** 操作：

   - [ ] 用关键词 Grep `~/.claude/skills/` 和相关项目 `.claude/skills/` 文件，检查内容重叠
   - [ ] 检查 MEMORY.md（项目和全局）是否有重叠
   - [ ] 考虑追加到现有技能是否就足够了
   - [ ] 确认这是可复用的模式，不是一次性修复

   ### 5b. 综合裁定

   综合检查清单结果和草稿质量，然后选择以下 **一项**：

   | 裁定 | 含义 | 下一步操作 |
   |---------|---------|-------------|
   | **保存** | 独特、具体、范围恰当 | 继续到第 6 步 |
   | **改进后保存** | 有价值但需要完善 | 列出改进项 → 修订 → 重新评估（一次） |
   | **合并到 [X]** | 应追加到现有技能 | 展示目标技能和新增内容 → 第 6 步 |
   | **放弃** | 琐碎、冗余或太抽象 | 解释原因并停止 |

   **指导维度**（影响裁定，不评分）：

   - **具体性和可操作性**：包含可立即使用的代码示例或命令
   - **范围适合度**：名称、触发条件和内容对齐，聚焦于单一模式
   - **独特性**：提供现有技能未覆盖的价值（基于检查清单结果）
   - **可复用性**：未来会话中存在现实的触发场景

6. **裁定特定的确认流程**

   - **改进后保存**：展示所需改进 + 修订后草稿 + 更新后的检查清单/裁定；如修订后裁定为 **保存**，用户确认后保存，否则遵循新裁定
   - **保存**：展示保存路径 + 检查清单结果 + 一行裁定理由 + 完整草稿 → 用户确认后保存
   - **合并到 [X]**：展示目标路径 + 新增内容（diff 格式） + 检查清单结果 + 裁定理由 → 用户确认后追加
   - **放弃**：仅显示检查清单结果 + 原因（无需确认）

7. 保存/合并到确定的位置

## 第 5 步的输出格式

```
### 检查清单
- [x] skills/ grep：无重叠（或：发现重叠 → 详情）
- [x] MEMORY.md：无重叠（或：发现重叠 → 详情）
- [x] 现有技能追加：适合创建新文件（或：应追加到 [X]）
- [x] 可复用性：已确认（或：一次性 → 放弃）

### 裁定：保存 / 改进后保存 / 合并到 [X] / 放弃

**理由：**（1-2 句解释裁定）
```

## 设计理由

此版本将之前的 5 维数字评分标准（具体性、可操作性、范围适合度、非冗余性、覆盖度各评 1-5 分）替换为基于检查清单的综合裁定系统。现代前沿模型（Opus 4.6+）具有强大的上下文判断力 — 将丰富的定性信号强制转为数字评分会失去细微差别，可能产生误导性总分。综合方法让模型自然权衡所有因素，产生更准确的保存/放弃决策，同时显式检查清单确保不遗漏关键检查。

## 注意事项

- 不要提取琐碎的修复（拼写错误、简单语法错误）
- 不要提取一次性问题（特定 API 中断等）
- 聚焦于能在未来会话中节省时间的模式
- 保持技能聚焦 — 每个技能一个模式
- 当裁定为合并时，追加到现有技能而非创建新文件
