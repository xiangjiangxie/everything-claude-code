# 保存会话命令

捕获本次会话中发生的所有内容 — 构建了什么、什么可行、什么失败、还剩什么 — 并写入日期文件，以便下次会话可以从断点精确恢复。

## 使用场景

- 关闭 Claude Code 前的工作会话结束时
- 接近上下文限制前（先运行此命令，然后开始新会话）
- 解决了想要记住的复杂问题后
- 任何需要将上下文交接给未来会话的时候

## 流程

### 第 1 步：收集上下文

写入文件前，收集：

- 读取本次会话中修改的所有文件（使用 git diff 或从对话中回忆）
- 回顾讨论、尝试和决策的内容
- 记录遇到的错误及其解决方式（或未解决）
- 如相关，检查当前测试/构建状态

### 第 2 步：创建会话文件夹（如不存在）

在用户的 Claude 主目录创建规范的会话文件夹：

```bash
mkdir -p ~/.claude/session-data
```

### 第 3 步：写入会话文件

创建 `~/.claude/session-data/YYYY-MM-DD-<short-id>-session.tmp`，使用当天实际日期和满足 `session-manager.js` 中 `SESSION_FILENAME_REGEX` 规则的短 ID：

- 兼容字符：字母 `a-z` / `A-Z`、数字 `0-9`、连字符 `-`、下划线 `_`
- 兼容最小长度：1 个字符
- 新文件推荐风格：小写字母、数字和连字符，8+ 个字符以避免冲突

有效示例：`abc123de`、`a1b2c3d4`、`frontend-worktree-1`、`ChezMoi_2`
新文件应避免：`A`、`test_id1`、`ABC123de`

完整有效文件名示例：`2024-01-15-abc123de-session.tmp`

旧格式文件名 `YYYY-MM-DD-session.tmp` 仍然有效，但新会话文件应优先使用短 ID 形式以避免同日冲突。

### 第 4 步：填充文件的所有章节

如实写入每个章节。不要跳过章节 — 如果某章节确实没有内容，写"暂无"或"不适用"。不完整的文件比诚实的空章节更糟。

### 第 5 步：向用户展示文件

写入后，显示完整内容并询问：

```
会话已保存到 [实际解析的会话文件路径]

这看起来准确吗？关闭前有需要更正或补充的内容吗？
```

等待确认。如有要求则进行修改。

## 输出示例

```markdown
# Session: 2024-01-15

**Started:** ~2pm
**Last Updated:** 5:30pm
**Project:** my-app
**Topic:** 使用 httpOnly cookie 构建 JWT 认证

---

## 我们在构建什么

Next.js 应用的用户认证系统。用户通过邮箱/密码注册，
收到存储在 httpOnly cookie（非 localStorage）中的 JWT，受保护的路由
通过中间件检查有效 token。目标是在浏览器刷新后保持会话，
同时不将 token 暴露给 JavaScript。

---

## 已确认可行的内容（附证据）

- **`/api/auth/register` 端点** — 确认方式：Postman POST 返回 200，带用户
  对象，Supabase 仪表盘可见行记录，bcrypt 哈希正确存储
- **`lib/auth.ts` 中的 JWT 生成** — 确认方式：单元测试通过
  （`npm test -- auth.test.ts`），jwt.io 解码 token 显示正确负载
- **密码哈希** — 确认方式：测试中 `bcrypt.compare()` 返回 true

---

## 不可行的内容（及原因）

- **Next-Auth 库** — 失败原因：与我们的自定义 Prisma 适配器冲突，
  每次请求都抛出 "Cannot use adapter with credentials provider in this configuration"。
  不值得调试 — 对我们的设置来说过于固执己见。
- **将 JWT 存储在 localStorage** — 失败原因：SSR 渲染发生在
  localStorage 可用之前，导致每次页面加载都出现 React hydration 不匹配错误。
  此方案从根本上与 Next.js SSR 不兼容。

---

## 尚未尝试的内容

- 使用 `next/headers` 中的 `cookies()` 在服务器组件中读取 token
- 编写 middleware.ts 通过检查 cookie 存在来保护路由

- **自定义认证优于 Next-Auth** — 原因：Next-Auth 与我们的 Prisma 设置冲突，不值得折腾
```

## 注意事项

- 每个会话有自己的文件 — 绝不追加到之前的会话文件
- "不可行的内容"章节最关键 — 没有它，未来的会话会盲目重试失败的方案
- 如果用户要求在会话中途（而非结束时）保存，保存已知内容并清楚标记进行中的项目
- 该文件旨在下次会话开始时由 Claude 通过 `/resume-session` 读取
- 使用规范的全局会话存储：`~/.claude/session-data/`
- 任何新会话文件优先使用短 ID 文件名格式（`YYYY-MM-DD-<short-id>-session.tmp`）
