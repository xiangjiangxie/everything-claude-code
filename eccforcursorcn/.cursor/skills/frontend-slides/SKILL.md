# 前端幻灯片

创建零依赖、富动画效果的 HTML 演示文稿，完全在浏览器中运行。

灵感来源于 [zarazhangrui](https://github.com/zarazhangrui) 展示的视觉探索方法。

## 何时激活

- 创建演讲稿、路演幻灯片、工作坊幻灯片或内部演示文稿
- 将 `.ppt` 或 `.pptx` 幻灯片转换为 HTML 演示文稿
- 改进现有 HTML 演示文稿的布局、动效或排版
- 与尚未确定设计偏好的用户一起探索演示文稿风格

## 不可妥协的原则

1. **零依赖**：默认生成一个包含内联 CSS 和 JS 的独立 HTML 文件。
2. **视口适配是强制性的**：每张幻灯片必须适配一个视口，不允许内部滚动。
3. **展示而非描述**：使用视觉预览，而非抽象的风格问卷。
4. **独特设计**：避免通用的紫色渐变、Inter 白底等模板化外观。
5. **生产级质量**：保持代码有注释、可访问、响应式且性能良好。

生成前，阅读 `STYLE_PRESETS.md` 获取视口安全的 CSS 基础样式、密度限制、预设目录和 CSS 注意事项。

## 工作流程

### 1. 检测模式

选择一条路径：
- **新建演示文稿**：用户有主题、笔记或完整草稿
- **PPT 转换**：用户有 `.ppt` 或 `.pptx` 文件
- **增强优化**：用户已有 HTML 幻灯片，希望改进

### 2. 了解内容

只询问最少的必要信息：
- 用途：路演、教学、会议演讲、内部更新
- 长度：短（5-10 页）、中（10-20 页）、长（20+ 页）
- 内容状态：已完成的文案、粗略笔记、仅有主题

如果用户有内容，请他们在设计风格前先粘贴内容。

### 3. 探索风格

默认采用视觉探索方式。

如果用户已知道想要的预设，跳过预览直接使用。

否则：
1. 询问演示文稿应该营造什么感觉：令人印象深刻、充满活力、专注集中、深受启发。
2. 在 `.ecc-design/slide-previews/` 中生成 **3 个单页预览文件**。
3. 每个预览必须是独立的，清晰展示排版/配色/动效，幻灯片内容控制在约 100 行以内。
4. 询问用户保留哪个预览，或想混搭哪些元素。

在将情绪映射到风格时使用 `STYLE_PRESETS.md` 中的预设指南。

### 4. 构建演示文稿

输出格式为：
- `presentation.html`
- `[presentation-name].html`

仅当演示文稿包含提取的或用户提供的图片时才使用 `assets/` 文件夹。

必需的结构：
- 语义化的幻灯片 section
- 来自 `STYLE_PRESETS.md` 的视口安全 CSS 基础样式
- CSS 自定义属性用于主题值
- 用于键盘、滚轮和触摸导航的演示控制器类
- Intersection Observer 用于入场显示动画
- 减弱动效支持

### 5. 强制视口适配

将此视为硬性要求。

规则：
- 每个 `.slide` 必须使用 `height: 100vh; height: 100dvh; overflow: hidden;`
- 所有字体和间距必须使用 `clamp()` 缩放
- 当内容放不下时，拆分为多张幻灯片
- 永远不要通过缩小字体到不可读的大小来解决溢出问题
- 永远不允许幻灯片内部出现滚动条

使用 `STYLE_PRESETS.md` 中的密度限制和必需 CSS 块。

### 6. 验证

在以下尺寸检查最终演示文稿：
- 1920x1080
- 1280x720
- 768x1024
- 375x667
- 667x375

如果有浏览器自动化工具可用，用它来验证没有幻灯片溢出且键盘导航正常工作。

### 7. 交付

交接时：
- 删除临时预览文件，除非用户希望保留
- 在有用时使用平台对应的命令打开演示文稿
- 总结文件路径、使用的预设、幻灯片数量和便捷的主题自定义点

使用当前操作系统对应的打开命令：
- macOS: `open file.html`
- Linux: `xdg-open file.html`
- Windows: `start "" file.html`

## PPT / PPTX 转换

对于 PowerPoint 转换：
1. 优先使用 `python3` 配合 `python-pptx` 提取文本、图片和备注。
2. 如果 `python-pptx` 不可用，询问是否安装它或回退到手动/导出工作流。
3. 保留幻灯片顺序、演讲者备注和提取的资源。
4. 提取后，运行与新建演示文稿相同的风格选择流程。

保持转换的跨平台性。当 Python 可以完成工作时，不要依赖仅限 macOS 的工具。

## 实现要求

### HTML / CSS

- 使用内联 CSS 和 JS，除非用户明确要求多文件项目。
- 字体可以来自 Google Fonts 或 Fontshare。
- 优先使用氛围感背景、强类型层级和清晰的视觉方向。
- 使用抽象形状、渐变、网格、噪点和几何图形，而非插图。

### JavaScript

包含：
- 键盘导航
- 触摸/滑动导航
- 鼠标滚轮导航
- 进度指示器或幻灯片索引
- 入场显示动画触发器

### 无障碍

- 使用语义化结构（`main`、`section`、`nav`）
- 保持对比度可读
- 支持纯键盘导航
- 尊重 `prefers-reduced-motion`

## 内容密度限制

除非用户明确要求更高密度且可读性仍然良好，使用以下上限：

| 幻灯片类型 | 限制 |
|------------|------|
| 标题页 | 1 个标题 + 1 个副标题 + 可选标语 |
| 内容页 | 1 个标题 + 4-6 个要点或 2 个短段落 |
| 功能网格 | 最多 6 张卡片 |
| 代码展示 | 最多 8-10 行 |
| 引用页 | 1 条引言 + 出处 |
| 图片页 | 1 张图片，受视口约束 |

## 反模式

- 没有视觉识别度的通用初创公司渐变
- 除非有意为之的编辑风格，否则不使用系统字体
- 长段项目符号堆砌
- 需要滚动的代码块
- 在小屏幕上溢出的固定高度内容框
- 无效的 CSS 函数取反，如 `-clamp(...)`

## 相关 ECC 技能

- `frontend-patterns` 提供演示文稿周围的组件和交互模式
- `liquid-glass-design` 当演示文稿有意采用 Apple 玻璃拟态美学时使用
- `e2e-testing` 如果需要对最终演示文稿进行自动化浏览器验证

## 交付清单

- 演示文稿可在浏览器中从本地文件运行
- 每张幻灯片适配视口，无需滚动
- 风格独特且有意为之
- 动画有意义，不嘈杂
- 尊重减弱动效偏好
- 交付时说明文件路径和自定义点
