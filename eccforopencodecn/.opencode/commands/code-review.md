# 代码审查命令

审查代码变更的质量、安全性和可维护性：$ARGUMENTS

## 你的任务

1. **获取变更文件**：运行 `git diff --name-only HEAD`
2. **分析每个文件**的问题
3. **生成结构化报告**
4. **提供可操作的建议**

## 检查类别

### 安全问题（紧急）
- [ ] 硬编码的凭证、API 密钥、令牌
- [ ] SQL 注入漏洞
- [ ] XSS 漏洞
- [ ] 缺少输入验证
- [ ] 不安全的依赖
- [ ] 路径遍历风险
- [ ] 身份验证/授权缺陷

### 代码质量（高优先级）
- [ ] 函数超过 50 行
- [ ] 文件超过 800 行
- [ ] 嵌套深度超过 4 层
- [ ] 缺少错误处理
- [ ] console.log 语句
- [ ] TODO/FIXME 注释
- [ ] 公共 API 缺少 JSDoc

### 最佳实践（中等优先级）
- [ ] 可变模式（应使用不可变模式）
- [ ] 不必要的复杂性
- [ ] 新代码缺少测试
- [ ] 无障碍访问问题（a11y）
- [ ] 性能问题

### 风格（低优先级）
- [ ] 命名不一致
- [ ] 缺少类型注解
- [ ] 格式问题

## 报告格式

针对每个发现的问题：

```
**[严重程度]** file.ts:123
问题：[描述]
修复：[如何修复]
```

## 决策

- **紧急或高优先级问题**：阻止提交，要求修复
- **中等优先级问题**：建议在合并前修复
- **低优先级问题**：可选改进

---

**重要**：绝不批准包含安全漏洞的代码！
