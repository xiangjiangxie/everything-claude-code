# Go 审查命令

审查 Go 代码的惯用模式和最佳实践：$ARGUMENTS

## 你的任务

1. **分析 Go 代码**的惯用方式和模式
2. **检查并发** - goroutine、channel、mutex
3. **审查错误处理** - 正确的错误包装
4. **验证性能** - 内存分配、瓶颈

## 审查清单

### 惯用 Go
- [ ] 包命名（小写，无下划线）
- [ ] 变量命名（camelCase，简短）
- [ ] 接口命名（以 -er 结尾）
- [ ] 错误命名（以 Err 开头）

### 错误处理
- [ ] 错误已检查，未被忽略
- [ ] 错误包含上下文信息（`fmt.Errorf("...: %w", err)`）
- [ ] 适当使用哨兵错误
- [ ] 需要时使用自定义错误类型

### 并发
- [ ] Goroutine 管理得当
- [ ] Channel 缓冲区设置合理
- [ ] 无数据竞争（使用 `-race` 标志）
- [ ] 传递 Context 用于取消
- [ ] WaitGroup 使用正确

### 性能
- [ ] 避免不必要的内存分配
- [ ] 频繁分配使用 `sync.Pool`
- [ ] 小型结构体优先使用值接收器
- [ ] I/O 操作使用缓冲

### 代码组织
- [ ] 小而专注的包
- [ ] 清晰的依赖方向
- [ ] 私有代码使用 internal 包
- [ ] 导出项有 Godoc 注释
