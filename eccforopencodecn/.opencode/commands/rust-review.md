# Rust 审查命令

审查 Rust 代码的惯用模式和最佳实践：$ARGUMENTS

## 你的任务

1. **分析 Rust 代码**的惯用方式和模式
2. **检查所有权** - 借用、生命周期、不必要的克隆
3. **审查错误处理** - 正确的 `?` 传播，生产代码中不使用 unwrap
4. **验证安全性** - unsafe 使用、注入攻击、密钥

## 审查清单

### 安全性（紧急）
- [ ] 生产路径中无未检查的 `unwrap()`/`expect()`
- [ ] `unsafe` 块有 `// SAFETY:` 注释
- [ ] 无 SQL/命令注入
- [ ] 无硬编码密钥

### 所有权（高优先级）
- [ ] 无为满足借用检查器而进行的不必要 `.clone()`
- [ ] 函数参数中 `&str` 优先于 `String`
- [ ] 函数参数中 `&[T]` 优先于 `Vec<T>`
- [ ] 省略规则可用时无过多生命周期注解

### 错误处理（高优先级）
- [ ] 错误使用 `?` 传播；应用代码中使用 `anyhow`/`eyre` 的 `.context()`
- [ ] 无被静默的错误（`let _ = result;`）
- [ ] 库错误使用 `thiserror`，应用错误使用 `anyhow`

### 并发（高优先级）
- [ ] 异步上下文中无阻塞操作
- [ ] 优先使用有界 channel
- [ ] 已处理 `Mutex` 中毒
- [ ] `Send`/`Sync` 约束正确

### 代码质量（中等优先级）
- [ ] 函数少于 50 行
- [ ] 无深层嵌套（>4 层）
- [ ] 业务枚举使用穷尽匹配
- [ ] Clippy 警告已处理
