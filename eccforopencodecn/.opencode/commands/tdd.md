# TDD 命令

使用严格的测试驱动开发实现以下内容：$ARGUMENTS

## TDD 循环（必须遵守）

```
RED → GREEN → REFACTOR → REPEAT
```

1. **红色阶段**：先编写失败的测试
2. **绿色阶段**：编写最少的代码使测试通过
3. **重构阶段**：在保持测试通过的同时改进代码
4. **重复**：直到功能完成

## 你的任务

### 步骤 1：定义接口（脚手架）
- 定义输入/输出的 TypeScript 接口
- 创建函数签名，使用 `throw new Error('Not implemented')`

### 步骤 2：编写失败的测试（红色阶段）
- 编写测试来验证接口
- 包含正常路径、边界情况和错误条件
- 运行测试 - 验证它们失败

### 步骤 3：实现最小代码（绿色阶段）
- 只编写足够让测试通过的代码
- 不要过早优化
- 运行测试 - 验证它们通过

### 步骤 4：重构（改进阶段）
- 提取常量，改进命名
- 消除重复
- 运行测试 - 验证它们仍然通过

### 步骤 5：检查覆盖率
- 目标：最低 80%
- 关键业务逻辑 100%
- 如有需要添加更多测试

## 覆盖率要求

| 代码类型 | 最低要求 |
|-----------|---------|
| 标准代码 | 80% |
| 金融计算 | 100% |
| 身份验证逻辑 | 100% |
| 安全关键代码 | 100% |

## 需要包含的测试类型

- **单元测试**：独立函数
- **边界情况**：空值、null、最大值、边界值
- **错误条件**：无效输入、网络故障
- **集成测试**：API 端点、数据库操作

---

**必须遵守**：测试必须在实现之前编写。永远不要跳过红色阶段。
