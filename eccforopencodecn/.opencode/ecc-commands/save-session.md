# 保存会话命令

捕获此会话中发生的所有内容 — 构建了什么、什么有效、什么失败、还剩什么 — 并将其写入带日期的文件，以便下一个会话可以从上次中断的地方精确恢复。

## 何时使用

- 关闭 Claude Code 前的工作会话结束时
- 即将达到上下文限制时（先运行此命令，然后开始新会话）
- 解决了一个你想记住的复杂问题后
- 任何需要将上下文传递给未来会话的时候

## 流程

### 步骤 1：收集上下文

在写入文件之前，收集：

- 读取此会话期间修改的所有文件（使用 git diff 或从对话中回忆）
- 回顾讨论、尝试和决定的内容
- 记录遇到的任何错误及其解决方式（或未解决）
- 如果相关，检查当前的测试/构建状态

### 步骤 2：如果不存在则创建会话文件夹

在用户的 Claude 主目录中创建规范的会话文件夹：

```bash
mkdir -p ~/.claude/session-data
```

### 步骤 3：写入会话文件

创建 `~/.claude/session-data/YYYY-MM-DD-<short-id>-session.tmp`，使用今天的实际日期和满足 `session-manager.js` 中 `SESSION_FILENAME_REGEX` 规则的 short-id：

- 兼容字符：字母 `a-z` / `A-Z`、数字 `0-9`、连字符 `-`、下划线 `_`
- 兼容最小长度：1 个字符
- 新文件推荐风格：小写字母、数字和连字符，8 个以上字符以避免冲突

有效示例：`abc123de`、`a1b2c3d4`、`frontend-worktree-1`、`ChezMoi_2`
新文件应避免：`A`、`test_id1`、`ABC123de`

完整有效文件名示例：`2024-01-15-abc123de-session.tmp`

旧格式文件名 `YYYY-MM-DD-session.tmp` 仍然有效，但新会话文件应优先使用 short-id 格式以避免同日冲突。

### 步骤 4：填充文件的所有章节

如实写入每个章节。不要跳过章节 — 如果某个章节确实没有内容，写"暂无"或"不适用"。一个不完整的文件比一个诚实的空章节更糟糕。

### 步骤 5：向用户展示文件

写入后，显示完整内容并询问：

```
会话已保存到 [会话文件的实际解析路径]

这看起来准确吗？在我们关闭之前有什么需要更正或添加的吗？
```

等待确认。如有要求则进行编辑。

# 会话：2024-01-15

## 我们正在构建什么

Next.js 应用的用户认证系统。用户使用邮箱/密码注册，
收到存储在 httpOnly cookie 中（而非 localStorage）的 JWT，受保护的路由
通过中间件检查有效令牌。目标是在浏览器刷新时保持会话持久性，
同时不将令牌暴露给 JavaScript。

---

## 已确认有效的（附证据）

- **`/api/auth/register` 端点** — 确认方式：Postman POST 返回 200 并附带用户
  对象，Supabase 控制面板中可见行，bcrypt 哈希正确存储
- **`lib/auth.ts` 中的 JWT 生成** — 确认方式：单元测试通过
  （`npm test -- auth.test.ts`），jwt.io 上解码的令牌显示正确的载荷
- **密码哈希** — 确认方式：测试中 `bcrypt.compare()` 返回 true

---

## 无效的（及原因）

- **Next-Auth 库** — 失败原因：与我们自定义的 Prisma 适配器冲突，
  每次请求都抛出"Cannot use adapter with credentials provider in this configuration"。
  不值得调试 — 对我们的设置来说太有主见了。
- **将 JWT 存储在 localStorage 中** — 失败原因：SSR 渲染发生在
  localStorage 可用之前，每次页面加载都导致 React hydration 不匹配错误。
  此方法从根本上与 Next.js SSR 不兼容。

---

## 尚未尝试的

- 在登录路由响应中将 JWT 存储为 httpOnly cookie（最可能的解决方案）
- 使用 `next/headers` 中的 `cookies()` 在服务器组件中读取令牌
- 编写 middleware.ts 通过检查 cookie 存在性来保护路由

## 注意事项

- 每个会话有自己的文件 — 永远不要追加到之前会话的文件中
- "无效的"章节是最关键的 — 没有它，未来的会话会盲目重试失败的方法
- 如果用户要求在会话中途保存（不仅是在结束时），保存已知内容并清楚标记进行中的项目
- 该文件旨在通过 `/resume-session` 在下一个会话开始时由 Claude 读取
- 使用规范的全局会话存储：`~/.claude/session-data/`
- 新会话文件优先使用 short-id 文件名格式（`YYYY-MM-DD-<short-id>-session.tmp`）
